# Contributing

Read the [editorial policy](docs/methodology.md) before proposing sources or identities. Report vulnerabilities or exposed personal data privately (see [SECURITY.md](SECURITY.md)).

## Changes

- Short-lived branches from `main`; small, coherent PRs, squash-merged with an English Conventional Commits title (`feat: …`, `fix: …`, `docs: …`). Mark breaking changes.
- Required checks: `ci` (`.github/workflows/ci.yml`) and `CodeQL` (GitHub code scanning).
- `CHANGELOG.md` is generated by Release Please only. Never edit it; describe changes in the PR.
- No licence has been chosen. Do not copy third-party material or add a licence without maintainer agreement.
- Prefer simple code within the existing [architecture](docs/architecture.md); no abstractions for hypothetical needs.
- Ship PostgreSQL migrations with model changes.
- Never commit secrets, dumps, real records or source documents. A committed secret must be rotated, not just removed.

## Testing

- Use a disposable PostgreSQL database, never SQLite or production credentials.
- Test fixtures are deterministic and fictional.
- Test consumer-visible behaviour and trust boundaries, not wiring or wording.
- Exercise data/schema migrations with committed legacy rows; empty-database checks do not cover deferred foreign-key events or record preservation.
- Check UI changes in a real browser, including keyboard use and mobile widths.

## Agents

Agents need explicit permission to push, deploy, publish data, read secrets or change infrastructure.
